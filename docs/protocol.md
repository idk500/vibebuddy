# VibeCoding Companion — Relay Hub Protocol

This document defines the Phase 1.5 protocol between adapters, the Relay Hub, and the phone PWA.

## 1. Roles

| Role | Transport | Description |
|------|-----------|-------------|
| Adapter → Relay Hub | HTTP JSON | Tool/plugin registers itself and sends events |
| Relay Hub → Phone | WebSocket JSON | Hub broadcasts status/log/prompt/ACK messages |
| Phone → Relay Hub | WebSocket JSON | Phone sends prompt replies and commands |
| Adapter ← Relay Hub | HTTP JSON polling | Adapter polls for replies destined to its `sourceId` |

## 2. Identifiers

| Field | Required | Meaning |
|-------|----------|---------|
| `sourceId` | Required for adapter events and replies | Unique adapter/tool instance |
| `sessionId` / `sessionID` | Recommended | Tool conversation/task session |
| `id` | Required on prompt events | Prompt request ID generated by adapter/tool |
| `requestID` | Required on phone replies | The prompt request ID being answered |
| `ackId` | Recommended on phone replies | Correlates phone action with `reply_ack` |

The Relay Hub routes replies by `sourceId + requestID`.

## 3. Adapter HTTP API

### 3.1 Register source

```http
POST /api/register
Content-Type: application/json
```

Request:

```json
{
  "sourceId": "opencode:1234:abcd",
  "tool": "opencode",
  "name": "OpenCode 1234",
  "serverUrl": "http://localhost:4096/",
  "cwd": "E:\\AI",
  "capabilities": ["events", "permission.ask", "question.asked"]
}
```

Response:

```json
{"ok": true, "sourceId": "opencode:1234:abcd"}
```

### 3.2 Send event

```http
POST /api/event
Content-Type: application/json
```

Status event:

```json
{
  "type": "status",
  "sourceId": "opencode:1234:abcd",
  "sessionId": "ses_1",
  "status": "THINKING",
  "task": "Generating response...",
  "duration": 0,
  "toolCount": 0,
  "errorCount": 0
}
```

Tool event:

```json
{
  "type": "tool",
  "sourceId": "opencode:1234:abcd",
  "sessionId": "ses_1",
  "id": "tool-call-1",
  "name": "bash",
  "status": "started",
  "args": {},
  "title": "Run tests",
  "ts": 1760000000000
}
```

`id` is optional but recommended. When present, phone clients use it to avoid double-counting `started` plus `completed`/`failed` updates for the same tool call.

Permission event:

```json
{
  "type": "permission",
  "sourceId": "opencode:1234:abcd",
  "sessionId": "ses_1",
  "sessionID": "ses_1",
  "id": "per_1",
  "tool": "bash",
  "message": "Allow this command?",
  "patterns": ["npm test"]
}
```

Question event:

```json
{
  "type": "question",
  "sourceId": "opencode:1234:abcd",
  "sessionId": "ses_1",
  "sessionID": "ses_1",
  "id": "que_1",
  "questions": [
    {
      "header": "Choose option",
      "question": "How should this be handled?",
      "options": [
        {"label": "Yes", "description": "Proceed"},
        {"label": "No", "description": "Stop"}
      ]
    }
  ]
}
```

If an event is `permission` or `question` and contains `sourceId` plus `id`, the Relay Hub creates a pending request.

### 3.3 Poll replies

```http
GET /api/replies?sourceId=opencode%3A1234%3Aabcd
```

Response with no replies:

```json
{"ok": true, "replies": []}
```

Permission reply:

```json
{
  "ok": true,
  "replies": [
    {
      "ackId": "ack_1",
      "kind": "permission",
      "sourceId": "opencode:1234:abcd",
      "sessionId": "ses_1",
      "requestId": "per_1",
      "reply": "once",
      "ts": 1760000000000
    }
  ]
}
```

Question reply:

```json
{
  "ok": true,
  "replies": [
    {
      "ackId": "ack_2",
      "kind": "question",
      "sourceId": "opencode:1234:abcd",
      "sessionId": "ses_1",
      "requestId": "que_1",
      "answers": [["Yes"]],
      "ts": 1760000000000
    }
  ]
}
```

Polling drains the current queue for that source.

## 4. WebSocket server messages

### 4.1 Connected

```json
{"type":"connected","serverVersion":"0.1.0","sessionId":null}
```

### 4.2 Source status

```json
{
  "type": "source",
  "sourceId": "opencode:1234:abcd",
  "tool": "opencode",
  "name": "OpenCode 1234",
  "status": "registered",
  "ts": 1760000000000
}
```

### 4.3 Permission prompt

Same shape as adapter `permission` event; forwarded to all connected PWA clients.

### 4.4 Reply ACK

```json
{
  "type": "reply_ack",
  "ackId": "ack_1",
  "requestId": "per_1",
  "sourceId": "opencode:1234:abcd",
  "sessionId": "ses_1",
  "status": "accepted",
  "message": "optional detail"
}
```

ACK statuses:

| Status | Meaning |
|--------|---------|
| `accepted` | Reply was queued for the adapter source |
| `failed` | Missing source, missing pending request, or invalid route |
| `expired` | Pending request existed but timed out before reply |

## 5. WebSocket phone messages

### 5.1 Permission reply

```json
{
  "type": "permission_reply",
  "ackId": "ack_1",
  "sourceId": "opencode:1234:abcd",
  "sessionId": "ses_1",
  "requestID": "per_1",
  "reply": "once"
}
```

Allowed `reply` values:

- `once`
- `always`
- `reject`

Relay Hub maps `once`/`always` to an adapter reply. The OpenCode plugin maps `once`/`always` to `output.status = "allow"` and `reject` to `output.status = "deny"`.

### 5.2 Question reply

```json
{
  "type": "question_reply",
  "ackId": "ack_2",
  "sourceId": "opencode:1234:abcd",
  "sessionId": "ses_1",
  "requestID": "que_1",
  "answers": [["Yes"]]
}
```

### 5.3 Question reject/skip

```json
{
  "type": "question_reject",
  "ackId": "ack_3",
  "sourceId": "opencode:1234:abcd",
  "sessionId": "ses_1",
  "requestID": "que_1"
}
```

The Relay Hub translates this to `answers: []` for the adapter queue.

## 6. Compatibility endpoints

### 6.1 Test broadcast

```http
POST /api/test
```

Broadcasts arbitrary JSON to connected PWA clients. This is for diagnostics only.

### 6.2 Legacy config

```http
POST /api/config
```

Accepts the old OpenCode server URL registration shape:

```json
{"opencodeUrl":"http://localhost:4096/"}
```

This endpoint remains for compatibility and diagnostics. Reliable remote approval should use source-bound `/api/event` plus `/api/replies`, not global URL forwarding.

## 7. Safety and routing rules

- A phone reply without `sourceId` is rejected with `reply_ack.status = "failed"`.
- A phone reply whose `sourceId + requestID` is not pending is rejected with `failed`.
- A timed-out pending request is rejected with `expired`.
- Successful replies are enqueued only for the exact `sourceId`.
- Relay Hub state is in memory and cleared on restart.
